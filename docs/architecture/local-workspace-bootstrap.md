# Local workspace bootstrap

`npm run local-workspace:bootstrap` is read-only by default. It checks only the
exact normalized user email plus active workspace name plus owner membership;
it does not pick the first user/workspace or repair another tenant.

Optional, non-secret identity overrides:

- `REKLAMZEKA_BOOTSTRAP_USER_EMAIL`
- `REKLAMZEKA_BOOTSTRAP_WORKSPACE_NAME`
- `REKLAMZEKA_BOOTSTRAP_WORKSPACE_REF`
- `REKLAMZEKA_BOOTSTRAP_READER_REF`
- `REKLAMZEKA_BOOTSTRAP_LOCAL_ORIGIN` (must be an exact `http://localhost` origin)

Run the safe preview first:

```sh
npm run local-workspace:bootstrap
```

Create or reuse the exact binding explicitly:

```sh
npm run local-workspace:bootstrap -- --apply
```

Apply uses one serializable transaction and a transaction-scoped advisory lock.
All inserted UUIDs are generated by PostgreSQL defaults. A same-named workspace
owned by a different user is not adopted or changed. Creation records a
`local_workspace.bootstrap_created` audit event.

The command never prints UUIDs, the database URL, tokens, or signing keys. After
apply it atomically writes the non-secret identity bindings to the git-ignored
`.reklamzeka/local-session-config` with mode `0600`. Preview and then explicitly
apply the private `.env.local` binding:

```sh
npm run local-session:configure
npm run local-session:configure -- --apply
```

The apply command replaces only the namespaced local-session keys, preserves all
other env values, reuses a valid signing key or creates one with 32 random bytes,
and never prints values. Both source and target must be owner-only regular files.
The existing `localDecisionRoomConfig` env contract is unchanged.

The applied-database acceptance check is intentionally separate:

```sh
npm run verify:local-workspace-bootstrap-db
```

It creates fixtures only inside an outer transaction, verifies idempotency,
audit, and foreign-tenant isolation, then rolls everything back. It makes no
Meta, HTTP, or other network calls beyond the configured PostgreSQL connection.
